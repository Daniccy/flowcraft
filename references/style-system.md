
# FlowCraft Visual System

## 1. 品牌定位
**从业务逻辑到专业视觉表达。**
英文表达：**Turn Business Logic into Professional Visuals.**

视觉关键词：Professional、Structured、Clear、Calm、Editable。
目标是形成适合技术评审、方案汇报、产品沟通和知识传播的视觉资产，而不是海报式装饰图。

## 2. 默认颜色 Token

| Token | Value | 默认语义 |
|---|---|---|
| canvas | `#F7F9FC` | 画布背景 |
| surface | `#FFFFFF` | 分区容器与卡片 |
| border | `#DBE2EA` | 细描边 |
| text-primary | `#17253C` | 标题、关键节点 |
| text-secondary | `#53647D` | 正文说明 |
| text-muted | `#8290A5` | 辅助信息 |
| blue | `#2563EB` | 主流程、核心路径 |
| amber | `#B96B08` | 处理机制、策略 |
| green | `#26764B` | 校验、成功、完成 |
| red | `#C34242` | 风险、失败、门禁 |
| purple | `#9333EA` | 反馈、规则沉淀、版本演进 |

浅色底：blue-soft `#EFF6FF`、amber-soft `#FFF7ED`、green-soft `#F0FDF4`、red-soft `#FEF2F2`、purple-soft `#F5F3FF`。

颜色映射是默认建议。每张图必须先定义颜色语义，并在图例中解释。颜色语义应随业务而变化，不要机械套色。

## 3. 字体与字号
字体栈：
`PingFang SC, Microsoft YaHei, Noto Sans CJK SC, Helvetica Neue, Arial, sans-serif`

以约 1800–2000px 宽画布为参考：
- 主标题：34–40px；
- 副标题：20–26px；
- 分区标题：24–28px；
- 节点标题：20–24px；
- 节点说明：17–21px；
- 图例和注释：15–18px。

不要无限缩小字体解决拥挤。扩大画布、拆图或精简重复文字，但不得丢失业务语义。

## 4. 布局规则
- 标题区：左侧窄色条、主标题、副标题；右侧可放版本、范围或说明。
- 分区容器：白色背景、浅灰描边、12–16px 圆角。
- 节点卡片：10–12px 圆角，1–1.5px 描边。
- 同级节点统一尺寸和间距；
- 重要参数单独成行；
- 主流程明显，异常和反馈路径不应喧宾夺主；
- 底部说明条可放预算、边界、注意事项；
- 图例解释颜色和线型。

## 5. 连线语言
默认建议：
- 蓝色实线：主流程；
- 灰色实线：一般依赖或辅助连接；
- 灰色虚线：循环、重试或回流；
- 红色虚线：异常升级、风险路径；
- 紫色虚线：规则反馈和版本反哺；
- 绿色实线：成功、通过或完成。

所有连线必须有明确起点、终点和方向。关键分支标注条件。优先使用直角/正交走线，避免穿过节点正文。

## 6. 形状语言
- 圆角矩形：处理步骤、系统模块；
- 菱形：真实的条件判断；
- 圆柱或存储符号：数据存储；
- 文档形状：文件、报告和产物；
- 独立泳道/角色卡片：参与者和责任边界；
- 大容器：系统边界、阶段或逻辑分区。

不要为了装饰而滥用形状和图标。

## 7. 适配不同图形类型
- 系统架构：按系统边界、组件层级、依赖关系组织；
- Agent 架构：突出 Agent、工具、记忆、路由、反馈和人工介入；
- 数据流：突出数据源、转换、存储、消费和权限边界；
- 时序图：突出参与者、消息方向和时间顺序；
- 泳道图：按角色/系统划分责任边界；
- 治理闭环：突出识别、复核、处置、反馈和规则迭代；
- 指标框架：突出指标分组、定义、口径和依赖关系。

## 8. 禁用倾向
- 大面积渐变、玻璃拟态和厚重阴影；
- 高饱和颜色过多；
- 无语义装饰图标；
- 为对称而扭曲真实关系；
- 把所有图都套成固定三栏；
- 为了短小而删掉异常路径和约束；
- 只输出不可编辑截图。
