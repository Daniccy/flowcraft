# License decision — before public launch

A public GitHub repository is not automatically open source. If no license is present, default copyright generally applies.

Choose intentionally:

## Option A — MIT (recommended for a genuinely open Lite core)
- Very permissive;
- Allows commercial use, modification and redistribution;
- Requires preserving copyright and license notice;
- Makes adoption easy, but others can reuse the Skill commercially.

## Option B — Apache-2.0
- Permissive, with explicit patent-related terms;
- Suitable for projects that want clearer patent terms;
- More text and obligations than MIT.

## Option C — All rights reserved / source-available
- Public users can inspect the repository;
- No implied permission to redistribute or reuse;
- Less aligned with community adoption and open-source contribution.

Suggested split:
- Public repository: MIT or Apache-2.0 for Lite/core files, if the maintainer accepts reuse.
- Paid services, private templates, hosted execution, custom integrations and support: separate commercial terms.
- Do not publish paid files into the public repository by accident.

Do not add a license until the maintainer chooses the intended reuse rights.
